# 匿名提出・ブラインドレビューの追加監査

匿名性は「氏名がない」ではなく、提出物・公開アカウント・外部情報を組み合わせて応募者を特定できる経路がないかという観点で評価する。完全な匿名性は保証できない。識別経路が見つからない場合も「検出なし」と報告し、「匿名保証」とはしない。

## 対象を先に固定する

- 提出条件（匿名性、GitHub所有者、許可される履歴やリンク、ファイル形式）を確認する。提示されていない条件は推測で補わない。
- **Git push**：提出するrefから到達可能なコミット・ツリー・タグ・LFS等と、指定した公開リポジトリの表示情報を調査する。ローカルのstashや到達不能オブジェクトは通常pushされないため別枠にする。
- **ファイルアップロード**：実際のアップロード対象とその内部メタデータを調査する。既存リポジトリの全履歴を公開するものとして扱わない。
- **既存Private→Public**：GitHub上に既存のブランチ、タグ、Release、公開可能となる関連データがないかも調査する。ローカルだけで確認できなければ未確認とする。

## 識別経路

1. **Git履歴**：author/committerの氏名・メール・日時・メッセージ、署名、注釈付きタグ。単一コミットやnoreplyアドレスでも個人識別可能な場合がある。
2. **提出ファイル**：氏名・ハンドル・個人URL・連絡先・端末名・絶対パス・所在地・学校/所属、Notebookの出力や実行パス、埋め込み文書の著者情報、画像EXIFや動画メタデータ。
3. **アカウント/外部リンク**：GitHubオーナー名、プロフィール、既存活動との連結、READMEやバッジ・画像・外部サイトへのリンク、公開後のコミット履歴。
4. **提出要件**：匿名用アカウントの可否、履歴の許容範囲、審査中の公開ルール。公開情報が見られないものは未確認。

見つかった識別情報は生の値を回答に転記せず、場所・種別・識別の可能性だけを示す。

## 推奨対応の出し方

- 現リポジトリを直接改変するより、**提出物のみを別の作業ディレクトリへ複製し、元の `.git` を含めない**方針を第一候補にする。これは提案であり自動実行しない。
- 匿名用の新規履歴が必要なら、課題要件を満たすauthor/committer情報・署名設定・コミット数・提出ファイルだけを再検査する。
- 公開前にrefと提出内容を、公開後にGitHub側の所有者・コミット・ファイルをそれぞれ確認するよう案内する。
- コードを別アカウントで再公開しても、特徴的なコード・公開済み履歴・リンクで元アカウントと関連付けられる可能性を明示する。
