# 匿名提出・ブラインドレビューの追加監査

匿名提出では、氏名の有無だけでなく、提出物・公開アカウント・外部情報を組み合わせて本人を特定できる可能性を調べる。完全な匿名性は保証できない。識別につながる情報が見つからなくても「検出なし」と報告し、「匿名性を保証する」とは書かない。

## 公開・提出の対象を確認する

- 提出要件（匿名性、GitHubの所有者、許可される履歴やリンク、ファイル形式）を確認する。不明な条件は推測で補わない。
- **Git push**：提出するrefから到達可能なコミット・ツリー・タグ・LFSなどと、公開先リポジトリの表示情報を調べる。ローカルのstashや到達不能オブジェクトは通常pushされないため、公開対象とは分ける。
- **ファイルのアップロード**：実際にアップロードするファイルと、内部のメタデータを確認する。既存リポジトリの全履歴まで公開されるものとして扱わない。
- **既存のPrivateリポジトリのPublic化**：GitHub上のブランチ、タグ、Release、公開され得る関連データも調べる。ローカルだけでは確認できないものは未確認とする。

## 個人を特定できる情報

1. **Git履歴**：作者・コミッターの氏名やメールアドレス、日時、コミットメッセージ、署名、注釈付きタグ。コミットが1件だけでも、作者情報が残る。noreplyアドレスも個人の特定につながる場合がある。
2. **提出ファイル**：氏名、ユーザー名、個人サイトのURL、連絡先、端末名、絶対パス、所在地、学校・所属、Notebookの出力や実行パス、文書の著者情報、画像のEXIFや動画のメタデータ。
3. **アカウントと外部リンク**：GitHubの所有者名やプロフィール、過去の活動との関連、README・バッジ・画像・外部サイトへのリンク、公開後に見えるコミット履歴。
4. **提出要件**：匿名用アカウントの利用可否、許可される履歴、審査期間中の公開ルール。確認できない要件は未確認とする。

識別につながる情報を見つけても、実際の値を報告に転記しない。場所、情報の種類、識別につながる理由を示す。

## 推奨対応

- 原則として、元のリポジトリを直接変更せず、**提出するファイルだけを別ディレクトリに複製し、元の `.git` は含めない**方法を提案する。実行はしない。
- 匿名用の新しい履歴が必要な場合は、課題要件に合う作者・コミッター情報、署名設定、コミット数、提出ファイルを再確認する。
- 公開前には提出するrefとファイルを、公開後にはGitHub上の所有者・コミット・ファイルを確認するよう案内する。
- 別アカウントで再公開しても、コードの特徴、公開済み履歴、リンクなどから元のアカウントとの関連が判明する可能性を明記する。
